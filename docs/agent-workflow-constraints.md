# Agent 工作流约束

> 适用于本项目及其后续会话。目标是用最少证据节点交付正确改动，避免测试、运行器和重复验证拖垮会话。

## 1. 最小证据工作流

普通任务固定为三个阶段：

1. **定位**：读取直接相关计划、Git diff 和必要代码片段。开放式 Explore 最多一次；已知文件禁止重复搜索。
2. **修改**：先确定边界，再成组修改。只处理用户要求和明确阻塞项。
3. **交付**：执行一次 `git diff --check`、一次 Error-only LSP，以及平台强制的正式入口 build，然后报告并停止。

普通任务目标为 6～9 个有效工具节点。超过预算前必须停止并回答：新调用是否会产生不可替代的新证据？不能则取消。

Todo 最多保留“定位、修改、交付”三项，只在阶段切换时更新。

## 2. 测试默认禁止

测试是高成本、高风险的外部操作，默认不执行。静态推导、局部代码审查、LSP 和正式构建可以覆盖的内容，禁止追加测试。

只有同时满足以下条件才允许测试：

- 用户在当前轮明确要求运行测试；
- 已有稳定、快速、可自动退出的定向测试入口；
- 不创建临时 harness，不切换正式入口，不启动 Preview；
- 测试直接覆盖本次改动，并提供静态分析无法获得的新证据；
- 执行成本明确且较低。

任一条件不满足，直接报告“测试未执行”或“运行行为未验证”。“未验证”是合法结论，不得为了消除该措辞继续调用工具。

禁止：

- 创建临时 `Start()`、临时测试入口、临时项目或测试构建配置；
- 把 `.project/project.json` 正式入口切换为测试脚本；
- 用 Runtime、Preview、截图或完整渲染承载单元测试；
- 自动运行完整回归、性能基准、随机压力测试或长时间渲染；
- 因“只差一个通过结果”而继续验证；
- 将超时、没有报错或进程仍存活描述为测试通过。

## 3. 首次异常立即停止

运行首次出现以下任一信号，本轮立即停止，不自动重试：

- timeout；
- watchdog；
- `Infinite loop detected`；
- 页面无响应；
- 重复调用栈或指令模式；
- 没有进入断言阶段；
- 进程不能自行退出。

禁止通过增加超时、修改入口、重复构建、关闭 watchdog 或 `BeginLongTask()` 绕过未知循环。`BeginLongTask()` 只能用于已经通过代码证明具有有限边界、且用户明确要求执行的离线任务。

只有发现明确代码原因并完成针对性修复后，才允许一次重试；没有代码变化禁止重试。第二次失败必须停止并标记未验证。

## 4. 质量证据优先级

按成本从低到高使用：

1. 数学与逻辑推导；
2. 受影响代码局部审查；
3. `git diff --check`；
4. Error-only LSP；
5. 平台要求的正式入口 build；
6. 用户明确要求时的最小定向测试。

不得用工具数量、测试数量或会话时长冒充质量。

## 5. 运行与预览

除非用户当前轮明确要求，否则不启动 Runtime、Preview、截图、服务器或长时间进程。UrhoX 代码修改后仍执行平台要求的正式 build，但只构建正式入口一次，不为测试切换入口。

## 6. 停止条件

以下条件满足后立即交付：

- diff 已审查一次；
- LSP Error 为 0；
- 平台强制 build 成功；
- 未执行的测试已诚实标记为未验证。

不得在没有新失败、新代码或新验收标准时重复检查。
